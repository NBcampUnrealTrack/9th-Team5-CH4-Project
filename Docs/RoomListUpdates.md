# 방 목록 변경 알림

Master의 `watch` HTTP 롱폴링을 사용한다. 최초 요청은 전체 Public 목록을 반환하고,
후속 요청은 cursor 기준 `changed`(추가/수정), `removed`(RoomId)만 반환한다.
20초 동안 변경이 없으면 빈 변경분으로 응답하며 클라이언트는 다음 요청을 보낸다.
Master는 0.2초 간격으로 공개 상태를 비교하므로 이 사이의 변경은 최종 상태로 합쳐진다.
게임 서버 인원/상태 반영은 서버 보고 도착 시점에 따른다.

변경 스냅샷은 최대 64개 유지한다. 알 수 없는 커서, Master 재시작, 통신 실패 이후에는
전체 스냅샷으로 복구한다. 구독 실패는 3초 후 재시도하며 생성/입장 요청을 차단하지 않는다.
구독은 인증된 클라이언트에 Public 방 전체를 제공하며 사용자별 목록 필터는 현재 없다.
동시 대기 구독 상한은 128개다.

UI는 RoomId별 UObject를 보관한다. 변경 시 기존 UObject에 데이터를 적용하고 OnChanged를
알려 해당 Entry만 갱신한다. 추가/삭제에는 ListView AddItem/RemoveItem을 사용한다.
Private 접속창, 목록 닫기, 서버 이동, 위젯 파괴 시 구독을 취소한다.
Private 창에서 돌아오거나 접속 실패로 복귀하면 구독을 다시 시작한다.

## 사용자 검증

- Master와 두 클라이언트를 같은 엔진으로 실행하고 한쪽에서 방을 생성한다.
- 다른 클라이언트의 목록에 새 방이 나타나는지 확인한다.
- 입장/퇴장 및 Waiting/Playing 변경 시 해당 행이 갱신되는지 확인한다.
- 마지막 인원 퇴장 후 방 삭제가 반영되는지 확인한다.
- Master 재시작 후 중복 행 없이 전체 목록으로 복구되는지 확인한다.
- 목록을 반복해서 열고 닫고 스크롤하여 재사용된 행의 잘못된 갱신이 없는지 확인한다.

`RoomService.Master.ReservationAndReplay`에 구독 대기, 인원 변경, 삭제, 커서 복구
검증을 추가했다. 코드 작성 시 빌드 및 자동화 테스트 실행은 하지 않았다.
